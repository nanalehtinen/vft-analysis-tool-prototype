Prototype for a Verbal Fluency Task Analysis Tool

Based on the validated administration & scoring protocol published in Lehtinen et al., (2023).

This is a prototype for a research tool for detailed scoring of verbal fluency task (VFT) performance: total score, errors, temporal parameters, and clustering and switching.

Components fully specified by deterministic rules are scored automatically; decisions involving semantic or linguistic interpretation are made by the researcher through a structured interface.

Uploaded data is processed locally and offline (on device), supporting GDPR-compliant data processing.

This prototype demonstrates the intended workflow and interface. It does not yet include the validated analysis engine — the results shown are the manual's own published worked examples.

Please see the Guidance tab for a full walkthrough, and the Scoring Rules tab for how scoring works and the full manual.

        Guidance

        A walkthrough of how this prototype works and how to read what it produces.

        Workflow

        The Start Here tab runs a seven-step setup, then a scoring pass that repeats for every trial in the batch, ending at the group-level results:

        1. 1
          Data languageDetermines the scoring rules and reference vocabulary used for clustering. Both Finnish and English are demonstrated here — the English path shows the intended state at the end of the funding period, since the validated English rule set is built during it. The interface itself is language-agnostic.
        2. 2
          Phonemic or semantic taskDetermines which clustering and switching rules apply to the transcript.
        3. 3
          Task promptPaste the exact instruction you gave the participant. Studies using the manual's wording can select it directly.
        4. 4
          Voice recordings or transcriptsSelect the format to upload your data. Written transcripts are demonstrated in this prototype.
        5. 5
          Confirm analysisReview a checklist of the scored metrics for your chosen task type.
        6. 6
          Number of trialsScore a single trial, or a batch — multiple trials answering one prompt, from one participant group. Everything above this point is set once and applies to the whole batch. The single-trial path uses the manual's published worked example, which is Finnish; batches use synthetic demo trials, in either language.
        7. 7
          Add your dataImport your transcripts, or voice files. A whole batch is imported once, here. For demonstration purposes, you can load a published example.
        8. 8
          Score the semantic clusteringRepeats for each trial. Semantic clustering is scored by the researcher, not by the tool. The response is shown in production order, and you drag across a run of words to group them into a cluster; anything you leave alone is a non-clustering single word. Because clusters are always contiguous runs, an invalid scoring — overlapping clusters, skipped words — cannot be produced. Mean cluster size and switches are then derived from the runs you defined. In a semantic trial this is the task-congruent reading; in a phonemic trial it is the task-discrepant one. Either way the phonemic reading stays rule-based, and the scoring is recorded in the results and the export so it stays auditable.
        9. 9
          Check that trial's resultsRepeats for each trial. The trial you just scored is shown in full — totals, errors, and both cluster breakdowns — so you can confirm the scoring before moving on. Continue to the next trial from here, or go back and revise. After the last trial this leads to the group results.
        10. 10
          Group results and downloadThe Results tab gives the group-level summary — mean, SD, range and n for each metric — with every trial listed beneath it, expandable to its full cluster breakdown. Results are downloadable here in CSV (one row per cluster, per trial) or JSON, ready to load into e.g. R, SPSS, or Python (pandas). Download is disabled in this prototype.

        Reading your results

        • Total score — acceptable words generated, minus errors.
        • Errors — repetitions, categorical errors, paraphasias and nonwords, each tagged with its type.
        • Temporal parameters — words per time segment; requires audio, so it's unavailable for transcript input in this prototype.

        Then, two clustering readings — scored independently per the manual:

        • Task-congruent clustering uses the same domain as the task — phonemic clusters (shared sounds, rhymes) in a phonemic trial, semantic clusters (shared meaning) in a semantic trial. This is the reading behind Mean cluster size and Number of switches.
        • Task-discrepant clustering is the other domain showing up anyway — e.g. a participant grouping words by meaning ("kynä, kumi" — things related to writing) while doing a phonemic task. It gets its own count and mean cluster size, since it reflects a distinct strategy. In a phonemic trial this reading is semantic, so you score it yourself and it is shown. In a semantic trial it is phonemic, which is not implemented yet — so it is shown as not calculated rather than as a result the tool can stand behind.
        • Cluster breakdown tables — every word accounted for, in the order the participant actually said it, including non-clustering single words.

        Results exist at two levels. Each trial gets its own full breakdown as you score it. The Results tab then aggregates the scalar metrics across the batch as mean, SD and range. The cluster breakdown is not aggregated — it is one participant's words in their own order, so there is no group version of it; instead each trial's breakdown stays available there for auditing.

        Development roadmap

        This prototype demonstrates the intended user experience. The tool itself is planned in phases:

        • Specification. Formalize the published protocol into a computable ruleset, sorting each rule by whether it can be resolved by deterministic logic, needs a citable linguistic reference, needs a semantic-relatedness component, or requires a design solution rather than automation.
        • Core engine and interface (Finnish). Build the deterministic components and the scoring interface, verify the implementation against the dataset used in the doctoral dissertation, and revise the workflow based on usability testing with speech-language pathology researchers.
        • English-language extension. Extend the deterministic components and interface to English, and validate against a subset of the existing immersed bilingual dataset scored independently by human raters. The English path in this prototype demonstrates the intended end state of this phase; the validated English rule set is the work itself.
        • AI feasibility study. Evaluate whether locally deployed multilingual models can reliably support selected rule-application edge cases — benchmarked in English first, then Finnish. Semantic clustering is excluded. AI support is integrated only if the findings warrant it.
        • Publication. A peer-reviewed manuscript on the tool's development and bilingual (Finnish/English) validation.

        How scoring works

        The tool combines automated, rule-based scoring with a structured interface for the decisions that require human expertise. It is built on two parts:

        1. Deterministic rules — automated. Total score, errors, temporal segmentation, and phonemic clustering follow explicit, mechanical rules from the manual. In method validation, two independent raters following these rules reached excellent agreement (ICC > 0.90) for phonemic cluster size and for both phonemic and semantic switches. Human judgment is very unlikely to be required here, and automated results remain overridable by the researcher.
        2. Structured human scoring. Semantic clustering is determined by the researcher, not by the tool. This is a deliberate design decision: semantic clustering depends on whether words are plausibly related enough to share a naturally occurring category, and it is the one component where validation showed lower agreement between trained raters (ICC 0.75–0.90 for semantic cluster size). The tool's role is to present each case clearly and record the decision, keeping scoring transparent and auditable.

        Under evaluation — AI-assisted decision support. A planned second stage will test whether locally deployed multilingual models can reliably support selected rule-application edge cases that deterministic rules cannot resolve. Semantic clustering is explicitly excluded from this scope. This support will only be built into the tool if a feasibility study demonstrates that model performance is adequate; if it is not, the documented decision will be not to proceed.
